Arquitetura

Uma requisição do navegador entra pela única porta exposta ao host (8080) e atravessa a rede virtual que o Compose cria. Dentro dela, os contêineres se encontram pelo nome do serviço — o nginx fala com backend, e a API fala com db e blockchain — sem nenhum IP fixo configurado.

host · localhost:8080
🖥️ navegador
rede do Compose · certificado_default
frontend nginx:1.27-alpine página + proxy /api
backend node:20-alpine API Express · relayer
db postgres:16-alpine dados pessoais (LGPD) ⛁ volume pgdata
blockchain node:20-bookworm nó Hardhat + contrato ⛁ volume chain-shared

navegador → frontend:80 → backend:3000 → { db:5432 · blockchain:8545 }

A separação também é conceitual: o PostgreSQL guarda o que não pode ir a uma rede pública (mapa RA → nome, códigos gerados), enquanto o contrato recebe apenas IDs anônimos keccak256(sal + RA) e as regras de emissão — a mesma decisão LGPD do protótipo original, agora com fronteiras físicas entre os serviços.

Conceitos Docker aplicados

Dockerfile
São três: frontend/Dockerfile (nginx recebe a página e o proxy), backend/Dockerfile (instala dependências antes de copiar o código, aproveitando o cache de camadas, e roda como usuário node sem privilégios) e blockchain/Dockerfile (compila o contrato Solidity já no build da imagem, deixando o start do contêiner rápido).
Compose
O docker-compose.yml é o arquivo central: declara os quatro serviços, a ordem de subida (depends_on com service_healthy para o banco), as portas, os volumes e as variáveis. Um comando — docker compose up — levanta a aplicação inteira.
Redes de contêineres
O Compose cria uma rede virtual com DNS interno. A API se conecta ao banco pela URL postgres://…@db:5432/… e ao nó pela URL http://blockchain:8545 — nomes de serviço, não IPs. Só o frontend publica porta no host; banco e blockchain ficam inacessíveis de fora.
Volumes
Dois papéis diferentes: pgdata persiste o banco — derrubar e recriar o contêiner não apaga as inscrições; e chain-shared é um volume de comunicação: o nó publica ali o endereço e a ABI do contrato recém-implantado, e o backend lê ao subir, sem endereço hardcoded.
Variáveis de ambiente
Credenciais do Postgres, chave privada do relayer e o sal dos IDs anônimos vivem no .env (fora do versionamento) e chegam aos contêineres via Compose. O código lê process.env — nada sensível gravado em imagem ou repositório.

Painel do curso

O fluxo completo do contrato, operado pela página. Cada ação abaixo atravessa os quatro contêineres: a página envia à API, a API grava o off-chain no Postgres e assina a transação no nó Hardhat.

  1. Criar o curso

  2. Inscrever alunos

    Cole as linhas do CSV exportado do Google Forms — uma por aluno, no formato nome, e-mail, RA. Os nomes ficam no banco; só o hash vai ao contrato.

  3. Registrar presença professor como oráculo

  4. Encerrar o curso — emissão automática

    O contrato percorre os inscritos e emite sozinho os certificados de quem atingiu a frequência mínima. O professor não escolhe caso a caso.

  5. Avaliação anônima
