Sistemas Operacionais II — Prof. Douglas

Arthur Naoto Miura — FEMA/IMESA 2026

O Projeto

  • TCC: "Blockchain e Smart Contracts: barreiras à sua adoção"
  • Plataforma de certificados de cursos de extensão
  • Objetivo: containerizar com Docker + Compose
  • Antes: tudo local, sem isolamento entre componentes
  • Depois: 4 serviços independentes, 1 docker-compose.yml

Arquitetura

ServiçoImagem basePapel
frontend nginx:1.27-alpine Página estática + proxy /api → backend (sem CORS)
backend node:20-alpine API Express — relayer: Postgres + blockchain
db postgres:16-alpine Dados off-chain sensíveis (LGPD)
blockchain node:20-bookworm-slim Nó Hardhat — deploy do contrato no start

Única porta no host: :8080

Rede Virtual do Compose

navegador │ :8080 ▼ frontend (nginx) │ /api (proxy) ▼ backend (Express) ├──▶ db:5432 (PostgreSQL) └──▶ blockchain:8545 (Hardhat)

DNS interno — serviços se comunicam pelo nome

Volumes

pgdata
Banco persiste mesmo após docker compose down — dados não são perdidos entre reinicializações
chain-shared
Nó Hardhat publica contrato.json (endereço + ABI) no volume; backend lê o arquivo ao subir, sem hardcode de endereço

Outros Conceitos

  • Dockerfiles ×3 com cache de camadas — COPY package*.json antes do código; imagens alpine/slim; USER node no backend
  • depends_on + healthcheck — backend aguarda pg_isready do Postgres (condition: service_healthy)
  • .env fora do versionamento — credenciais nunca entram no repositório; código lê apenas process.env
  • Imagens alpine/slim — menor superfície de ataque, pulls mais rápidos

Decisão de Design — LGPD

🔗 Blockchain recebe keccak256(sal + ":" + RA) — identificador anônimo, imutável, público
🗄️ Postgres guarda nome, e-mail, RA — dados pessoais, podem ser deletados, fora da chain

Fronteira física entre contêineres — o backend é o único serviço que fala com ambos

Demo — localhost:8080

  1. Criar um curso: nome, carga horária, nº de aulas, presença mínima
  2. Inscrever alunos (nome, e-mail, RA) — nomes → Postgres; hashes → contrato
  3. Registrar presença aula a aula (professor como oráculo)
  4. Encerrar — contrato auto-emite certificados para quem atingiu frequência mínima
  5. Avaliação anônima — códigos embaralhados, notas pela "urna", média pública on-chain
  6. Verificar certificado — leitura pública, sem custo, pelo número impresso

Referência Rápida

docker compose up --build   # 1ª subida: build + start
docker compose up -d        # em segundo plano
docker compose ps           # status dos contêineres
docker compose logs -f backend
docker compose down         # para tudo (banco persiste)
docker compose down -v      # reset total (apaga banco e chain)

Resultado

  • ✓ Um único comando sobe toda a plataforma
  • ✓ Sem instalar Node, PostgreSQL ou Hardhat no host
  • ✓ Isolamento real: cada serviço com sua responsabilidade
  • ✓ Cache de camadas: rebuilds rápidos nas subidas seguintes
  • ✓ Pronto para demo: http://localhost:8080
